## 1. Критичные блокеры (Critical)

Эти проблемы блокируют запуск. Сайт нельзя выкатывать на anhelspb.com пока они не исправлены.

### C1. Три из шести пунктов главного меню — мёртвые ссылки

**Что сломано.**
- «О компании» → `/#about` — якоря `#about` в DOM нет, страницы `/about` тоже нет (404).
- «Производство» → `/#manufacturing` — якоря в DOM нет, страницы `/production` тоже нет (404).
- «Контакты» → `/#contact` — якоря в DOM нет, страницы `/contacts` тоже нет (404).

**Где видно.**
1. Открыть `/`.
2. Кликнуть в шапке «О компании».
3. Видим: ничего не происходит, скролл не меняется, hash в URL не появляется (router скрывает невалидный hash).

**Воспроизведение программно.** Из консоли на главной:
```js
document.getElementById('about')   // → null
document.getElementById('manufacturing')  // → null
document.getElementById('contact') // → null
```
Далее `fetch('/about')`, `fetch('/production')`, `fetch('/contacts')` → все возвращают **HTTP 404**.

**Почему критично.** B2B-клиент (девелопер, проектировщик, закупщик) первым делом ищет «Контакты» и «О компании» в шапке. Половина главного меню не работает — это полный отказ навигации. Из 13 ЖК Setl Group / ПИК ни один сейлз-менеджер с такой шапкой работать не сможет.

**Рекомендация.**
- Либо добавить эти три секции на главную с правильными `id` и плавным скролл-якорем,
- Либо превратить их в реальные страницы `/about`, `/production`, `/contacts` и обновить `href` в `Header.tsx` / `MobileMenu.tsx` / `Footer.tsx`.
- Промежуточный compromise недопустим: нельзя оставлять `/#about` без секции — клик по «О компании» не должен быть тихой no-op.

### C2. Подменю «Продукты» отсутствует — пользователь видит «пустой круг»

**Что сломано.** При hover на пункт «Продукты» в шапке вокруг текста появляется белая окружность (≈90 px диаметром). Пользователь принимает её за пустое выпадающее подменю и теряется.

**Что это на самом деле.** Это `anhel-cursor-active` — глобальный custom-cursor follower на `<body>`. Он присутствует на всех страницах, просто на «Продукты» совпадает с лейблом и выглядит как dropdown.

**Где видно.**
- `01_homepage_hero.jpg` (исходное состояние без hover).
- На `/products` после клика круг остаётся над любым местом, где курсор стоит, — это видно на скрине над картинкой «Тепловые пункты».

**Программное подтверждение.** Из DOM на любой странице:
```js
document.querySelector('[class*=submenu], [class*=dropdown], [class*=megamenu]')  // → null
```
То есть **подменю физически не реализовано**. Все 6 пунктов меню — простые `<a>` без вложенных `<ul>`.

**Почему критично.** Сценарий, описанный в ТЗ, повторяется один-в-один: «подменю при наведении на Продукты показывает только пустой круг». Скриншот пользователя — ровно эта ситуация. На каталог из 14+ продуктов нельзя попасть из шапки — нужно либо кликнуть «Продукты» (попадаешь на landing), либо угадать URL.

**Рекомендация.**
- Реализовать настоящий dropdown на `Продукты` с 4 категориями: Насосные станции (5 серий), ИТП (8 модулей), Водоподготовка, Шкафы управления (5 серий). Эталоны — terminal-industries.com, mont-fort.com.
- Параллельно: либо скрывать `anhel-cursor-active` при hover на интерактивные элементы (`a, button, input` → `cursor: none` / `display: none` для follower), либо менять его форму на «стрелку» / «клик» — индустриальные сайты обычно делают курсор-точку, а не курсор-окружность поверх текста.

### C3. LoadingSplash висит дольше, чем грузится контент

**Что сломано.** Серая заглушка с надписью `ANHEL®` показывается **поверх готового контента** заметно дольше, чем нужно. Замеры:

| Страница | Время до исчезновения splash |
|---|---|
| `/` (главная, повторный визит) | ~1 с (норм) |
| `/quiz/vpu` | ~7 с |
| `/projects` | ~9 с |
| `/service` | >5 с |
| `/service/request` | ~11 с |

**Где видно.** Скрин ss_5036t4pp9 (`/quiz/vpu`), ss_9987a49o4 (`/projects`), ss_58118pwgw (`/service`), ss_5062z4uhp (`/service/request`) — везде по центру серый `ANHEL®`, под ним просвечивают контент и заголовки.

**Почему критично.** Текущий коммит на main (`bf71ba2 fix(splash): unstick LoadingSplash + show only on first load and reload`) предполагает, что splash был починен. На production он по-прежнему накрывает все маршруты, кроме главной. Для пользователя 11 секунд чёрного экрана при заходе на `/service/request` (откуда инженер заполняет заявку!) выглядят как сломанный сайт.

**Рекомендация.**
- Подтвердить, что fix реально доехал на production (проверить, что Vercel задеплоил `bf71ba2`).
- Если задеплоился, но эффекта нет — снять триггер «show on every navigation» и оставить splash только на cold-start (первый pageview сессии).
- Время splash — макс 1.5 секунды (или сразу скрыть, как только React гидратировался).

### C4. Нет страниц `/privacy` и `/terms` — нарушение 152-ФЗ

**Что сломано.** На сайте есть формы, собирающие персональные данные (квизы, /service/request — ФИО, email, телефон, организация, ИНН). По 152-ФЗ обязательны:
- ссылка на политику обработки персональных данных в каждой форме,
- доступная страница политики конфиденциальности.

`fetch('/privacy')` → 404. `fetch('/terms')` → 404. В footer ссылок нет.

**Почему критично.** Любая жалоба в Роскомнадзор от конкурента или заказчика → штраф ст. 13.11 КоАП РФ (юр. лицо до 700 тыс. ₽). Также интеграции с любым CRM/Email-провайдером требуют отметку «согласен на обработку ПД».

**Рекомендация.**
- Создать `/privacy-policy` и `/personal-data-consent` (как минимум).
- Добавить чекбокс «Согласен с обработкой ПД» на финальный шаг каждого квиза и в `/service/request`.
- Ссылки на политику — в footer и под каждой формой.

## 2. Важные проблемы (Major)

### M1. Hero счётчики в infinite count-up — числа постоянно растут

**Где видно.** На главной в нижней части hero — три счётчика: ОБЪЕКТОВ / ЛЕТ ОПЫТА / НАПРАВЛЕНИЯ. Серия скриншотов:

| Время после загрузки | Объектов | Лет | Направлений |
|---|---|---|---|
| ~1 с | 128+ | 10 | 03 |
| ~3 с | 139+ | 11 | 04 |
| ~6 с | 150+ | 12 | 04 |

**Почему важно.** Числа должны застыть на финальном (например, «128+ объектов, 10 лет опыта, 4 направления»). Сейчас, видимо, цикл анимации уходит в бесконечность. Клиент видит «139+ объектов» через 3 секунды — теряется доверие.

**Рекомендация.** В компоненте счётчика снять `loop:true` / убрать повторный запуск. Финальное значение для «Объектов» взять из `_PROGRESS.md` (13 в каталоге, но в маркетинге допустимо «128+» как историческая цифра — главное не менять её на странице).

---

### M2. Несостыковка «3 направления» (caption на /products) vs «4 направления» (caption на главной) vs **4 карточки**

**Где видно.**

- `/` секция Products → заголовок «**Четыре** направления, одна сборка». Подзаголовок: «Насосные станции, водоподготовка, тепловые пункты и **шкафы управления**».
- `/products` → заголовок «Три направления». Подзаголовок: «Три направления — насосные станции (пять серий внутри), установки водоподготовки и блочные индивидуальные тепловые пункты». **Шкафы управления опущены.**
- При этом на `/products` рендерятся **4 карточки**, включая «Шкафы управления».

**Почему важно.** Это самая прямая нестыковка копирайта. Любой проектировщик пройдёт по странице каталога и увидит явное противоречие.

**Рекомендация.** Привести к одному числу. Учитывая что карточек 4 и шкафы реально есть в /products/control-systems с 5 сериями — везде писать «Четыре направления». Поправить копирайт на `/products` (и тексты в memory `project_section_4_installation_types.md`).

---

### M3. Hero текст «которые держат здание живым» — нечитаем в обеих темах

**Где видно.** На главной «Системы, которые держат здание живым» — два кегля:
- «Системы,» / «ЖИВЫМ.» — белый цвет, читается.
- «которые держат здание» — приглушённо-серый, читается с трудом на тёмном (контраст ≈3:1, WCAG AA требует ≥4.5:1 для крупного текста как минимум 3:1, тут на грани).
- В **светлой теме** этот же текст становится **светло-серым на светло-сером** (почти невидимый), см. скрин ss_9679cxbge.

**Почему важно.** Hero — первое впечатление. Низкий контраст = сайт выглядит «недоделанным», особенно в светлой теме, где главный заголовок частично исчезает.

**Рекомендация.** Поднять контраст серого до минимум `var(--color-text-secondary)` уровня. В светлой теме — переопределить цвет, вместо `light-grey` использовать `dark-grey`. Проверить через Chrome DevTools → Lighthouse Accessibility.

### M4. CTA «Опросный лист (Скоро)» в hero — выглядит дисабленным, при том что квизы работают

**Где видно.** На главной рядом с «Смотреть каталог» вторая кнопка «Опросный лист» с лейблом «СКОРО». Класс кнопки: `cursor-not-allowed`.

При этом `/quiz/pumps`, `/quiz/aupd`, `/quiz/itp`, `/quiz/vpu`, `/quiz/control-systems` все возвращают 200 OK с рабочим 5-шаговым квизом и формой.

**Почему важно.** Hero — главная точка конверсии. Кнопка «опросный лист» дисабленна, хотя сам опросный лист есть. Пользователь, увидев «Скоро», уходит. Это потеря лидов.

**Рекомендация.** Заменить кнопку на dropdown (или modal) «Выберите тип оборудования» с 5 пунктами → ссылки на соответствующие квизы. Снять класс `cursor-not-allowed`. Убрать лейбл «Скоро».

### M5. Hero carousel: 4 слайда сверху + 5 точек снизу — две несинхронные нумерации

**Где видно.** Над hero-заголовком: «**01 / 04** · ИНЖЕНЕРНОЕ ОБОРУДОВАНИЕ». Под hero справа: 5 круглых кнопок «01 02 03 04 05». Текст слайда: «Насосная станция водоснабжения».

**Почему важно.** Пользователь не понимает, сколько всего слайдов: 4 или 5? Нумерация в шапке слайдера не совпадает с пагинацией.

**Рекомендация.** Унифицировать на 4 (или 5, что есть на самом деле). Если slide #5 — это «итог»/«CTA» и не считается, переименовать пагинацию: «1·2·3·4 ●». Заодно положить slide-content всех 4–5 слайдов в репорт-комментарий, сейчас доступен только первый «Насосная станция водоснабжения».

### M6. На страницах модулей ИТП нет CTA «Заполнить онлайн»

**Где видно.** Программный обход 8 страниц `/products/heating-unit/{input-metering,open-heating,closed-heating,makeup,single-stage-dhw,two-stage-dhw,two-stage-dhw-monoblock,steam-condensate}` — на каждой 0 ссылок вида `href="/quiz/itp"`.

Для сравнения: на `/products/pumps/water-supply` и других pump-страницах — 1 ссылка `/quiz/pumps`. На страницах шкафов управления — даже 3 ссылки на `/quiz/control-systems`.

**Почему важно.** ИТП — самый сложный по подбору продукт. Опросный лист `/quiz/itp` существует и работает (5 шагов, 6 inputs). Но с 8 модулей пользователь его не достанет — нужно вручную набрать URL.

**Рекомендация.** Добавить в `HeatingUnitModulePage` блок «Заявка» / «Подбор онлайн» со ссылкой на `/quiz/itp`. Желательно с пред-заполнением типа модуля.

### M7. Footer — «Контакты» отсутствует в нав-блоке

**Где видно.** На любой странице в footer колонка «НАВИГАЦИЯ»: Продукты / Объекты / О компании / Производство / Сервис. Пять пунктов. В шапке — шесть, седьмой "Контакты". В footer его нет.

**Почему важно.** B2B-сайт без чёткой ссылки «Контакты» в подвале — серая зона. Контакты есть в соседнем блоке (телефон, email, адрес), но без явного якоря.

**Рекомендация.** Добавить пункт «Контакты» в footer-навигацию. Отдельно — связан с C1: если страницы `/contacts` нет, то и в footer её нельзя класть.

### M8. Footer — нет соцсетей, нет ссылок на политику

**Где видно.** Footer не имеет иконок Telegram / VK / etc. Также нет ссылок на политику конфиденциальности и пользовательское соглашение (см. C4).

**Почему важно.** Корпоративный B2B-сайт без соцсетей — не критично, но без политики конфиденциальности с формами — это блокер. Дублирую сюда для полноты.

**Рекомендация.** Минимум: добавить ссылки на `/privacy` и согласие на обработку ПД. Опционально: Telegram-канал ANHEL.

### M9. Фильтры на /projects — недостаточно категорий

**Где видно.** На `/projects` — фильтры «Все 13», «Насосные станции 13», «Водоподготовка 8».

**Почему важно.** Из 4 направлений каталога только 2 представлены в портфолио. Это либо тревожный сигнал («у нас нет реализованных проектов с ИТП и шкафами»), либо упущенный контент.

**Рекомендация.** Если объекты с ИТП и шкафами действительно есть — добавить фильтры. Если нет — убрать «Насосные станции» (overlapping с All). Заодно проверить, корректны ли тэги: на карточках видны теги «Насосные», «Насосные + Водоподготовка», но на 13 проектах все «Насосные» — может быть, тэги дублируются.

### M10. PDF на шкафах управления — только 1 (нет руководства, нет сертификата)

**Где видно.** На `/products/control-systems/variable-frequency` (и других 4 страницах серий) — 1 PDF: только опросный лист. Нет:

**Рекомендация.** Дозалить как минимум сертификат соответствия для шкафов, лучше плюс руководство по эксплуатации (унифицированное для серии).

## 3. Косметика (Minor)

### N1. URL `/products/pumps/firefighting` показывает TTFB ≈ 936 ms (warm), worst case в group
Cold-start ~32 с упомянут в ТЗ — на текущем замере (warm cache) этого нет. Тем не менее, страница достоверно медленнее остальных pump-страниц на 1.5×.

### N2. `/products/water-treatment` TTFB 1530 ms; `/products/control-systems/smoke-control` 2143 ms
Самые медленные warm-страницы каталога. Не блокирует, но Lighthouse-Performance score просядет.

### N3. Footer контакт-блок: «пом. 1-Н, Санкт-Петербург» на двух строках
Адрес читается, но «пом. 1-Н,» сидит на одной строке, «Санкт-Петербург» — на следующей. Лучше слить или разнести логично.

### N4. На квизах `/quiz/vpu`, `/quiz/control-systems` `<form>` тэг отсутствует — поля и кнопки рендерятся через React onClick без HTML form-обёртки
Не блокер, но фолбэк (Enter для submit, native browser autofill) работает не везде. На `/quiz/pumps`, `/quiz/aupd`, `/quiz/itp` — `<form>` есть.
