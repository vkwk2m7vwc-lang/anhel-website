## Краткое резюме

**P1-страницы в хорошем состоянии. Блокеров запуска нет.** Реальная
продуктовая фотография и рендеры, конкретный технический копирайт, честные
placeholder'ы там, где контент в работе. Все три локали (RU/EN/TR)
переведены полностью — RU-fallback не найден ни на одной P1-странице.
Dark-тема нигде не разваливается. Длинные TR-переводы вёрстку не ломают.

Найден **один сквозной паттерн** — тот же пустой desktop-hero, что
закрывали решением #3 на /products и /service. Он есть на двух
family-landing страницах (`/products/pumps`, `/products/control-systems`).
**Обе правки применены автономно** — это покрыто твоей пред-авторизацией
(эталон `7db772f`). Спрашивать было нечего.

Других правок, требующих твоего решения, по P1 нет. Несколько мелочей —
ниже, все косметические, не блокеры.

## Постранично

### `/documents` — ✅ ok
Hero одноколоночный типографический (уже в духе #3), карточки документов
читаемы, mobile стек 1-в-колонку. Каталоги — честный placeholder
«в подготовке». На EN/TR сертификаты ЕАЭС корректно помечены «Original
document (Russian)». Мелочь: на desktop нечётные группы (5 карточек)
оставляют полупустую последнюю строку. Подробно: `_audit/pages/documents.md`

### `/projects` — ✅ ok
Одна из самых сильных P1-страниц. Hero + фильтр по типу оборудования +
13 карточек объектов с реальными фото зданий, по каждому построчно указано
поставленное оборудование. Блок «Примечание» — честный дисклеймер про
неполную поставку. Подробно: `_audit/pages/projects.md`

### `/service/request` — ✅ ok
Многошаговая форма (5 шагов), аккуратно сделана. **Важно:** на full-page
скриншоте sticky-навигация выглядит наезжающей на поля — я проверил
viewport-only снимками: это headless-артефакт того же рода, что пустая
карта на /contacts. У реального пользователя — нормальная frosted-glass
панель, контент скроллится под ней, внизу панель отлипает в нормальный
поток. Мелочь: на mobile высокая «шапка» формы + sticky-бар сжимают
полезную площадь на первом экране (не баг, дизайн-решение). Подробно:
`_audit/pages/service-request.md`

### `/products/pumps` — ⚠️→✅ исправлено
Раздел-каталог насосных станций, 5 карточек серий с реальными рендерами.
Был пустой desktop-hero (#3) — исправлено автономно. Подробно:
`_audit/pages/products-pumps.md`

### `/products/control-systems` — ⚠️→✅ исправлено
Структурно идентичен /products/pumps. Был тот же пустой desktop-hero —
исправлено автономно. Подробно: `_audit/pages/products-control-systems.md`

### `/products/heating-unit` — ✅ ok
Полноценная продуктовая страница (не тонкий каталог): hero с рендером →
8 модулей → 6 преимуществ → галерея реальных фото → документация → CTA.
Мелочь: `line-clamp` в `AdvantagesGrid` режет описания 2 пунктов и длинное
название PDF-карточки. Подробно: `_audit/pages/products-heating-unit.md`

### `/products/water-treatment` — ✅ ok
Полноценная продуктовая страница: hero → ТТХ → описание → применение →
бренды → преимущества → галерея → кейсы → документация → CTA. Мелочи:
`BrandsStrip` на mobile визуально слегка «гуляет» (flex-wrap); тот же
`line-clamp` на преимуществах. Подробно:
`_audit/pages/products-water-treatment.md`

## Сквозные наблюдения

**Хорошо (подтверждено на всех 7 P1):**
- i18n RU/EN/TR — переведено полностью, fallback'ов нет, TR вёрстку не ломает
- Dark-тема — нигде не разваливается, контраст в норме
- Реальные фото и рендеры — сильная сторона: объекты, продуктовые рендеры,
  фото с производства. Сток / placeholder-картинок не найдено
- Честные placeholder'ы (Каталоги на /documents) — явно помечены «в работе»

**Паттерн-проблема (закрыта):**
- Пустой desktop-hero на каталожных family-landing (`/products/pumps`,
  `/products/control-systems`) — исправлен автономно по пред-авторизации

**Мелочи (косметика, не блокеры, твоё решение если захочется причёсывать):**
- `/documents` desktop — нечётные группы карточек, полупустая последняя строка
- `/service/request` mobile — высокая шапка формы + sticky-бар сжимают
  первый экран; есть дубль подписи шага («ШАГ 1 ИЗ 5» и «ШАГ 1 / 5»)
- `/products/heating-unit` + `/products/water-treatment` — `line-clamp` в
  `AdvantagesGrid` режет смысловую часть описаний у части пунктов
- `/products/water-treatment` — `BrandsStrip` на mobile неровно
  выкладывает названия брендов (flex-wrap «гуляет»)

**Артефакты скриншотов (НЕ баги — не путать):**
- `/service/request` — sticky-навигация на full-page скриншоте «наезжает»
  на поля. Проверено viewport-only снимками: штатное поведение sticky-панели
